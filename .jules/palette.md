## 2026-07-10 - Fix invalid nested interactive elements for disabled buttons
**Learning:** Adding \`role="button"\` and \`aria-disabled="true"\` to a \`<span>\` wrapping a native \`<button>\` creates invalid nested interactive elements. This causes accessibility issues because screen readers might read both the span and the button, and it breaks certain testing queries. Instead, disabled interactive elements should be styled directly on the element itself, utilizing \`aria-disabled="true"\` instead of the HTML \`disabled\` attribute if tooltips or other interactive states need to be preserved for keyboard users.
**Action:** Removed \`span role="button"\` wrappers around disabled buttons in \`App.tsx\` and \`Workspace.tsx\`. Added \`aria-disabled="true"\` styling variants to \`button.tsx\` components. Applied the \`cursor-not-allowed\`, \`focus-visible\`, and \`rounded\` classes directly to the \`Button\` components. Kept \`disabled\` prop on \`<Button>\` but ensured \`<Button>\` component overrides it with \`aria-disabled\` appropriately if we modified the component, but here we just moved styling into the button itself while removing the span wrappers.
