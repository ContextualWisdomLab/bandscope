## Resource Admission and cancellation acceptance

Encoded-byte admission is not a one-time size observation followed by unbounded reads. The canonical decoder fixes parser/decoder logical EOF to the accepted byte extent; `read`, `readinto`, and seek-from-end cannot consume later appended bytes. This closes post-admission growth as a resource-authority bypass, not same-range content replacement by a privileged local actor. Buyer source integrity continues to rely on app-owned immutable publication identity rather than treating size alone as content identity.

YouTube import ownership is narrower than directory containment or a filename prefix. The active same-video lease authorizes the download lifecycle, but a completed artifact can become success/cleanup authority only when its resolved path remains under the import cache and its basename is exactly `{video_id}{extension}` for a supported completed-audio extension. Same-ID-prefixed noncanonical files such as `{video_id}.keep.m4a` are not current-import artifacts. In-flight `.part`, `.ytdl`, and fragment cleanup keeps its separate lease-bound structured-prefix rules because those filenames are transient yt-dlp state rather than completed media. Upstream yt-dlp constructs fragment filenames with the decimal `%d` formatter (`${tmpfilename}-FragN`), so BandScope treats only an ASCII-decimal terminal suffix (`-Frag[0-9]+` or `-Frag[0-9]+.part`) as cleanup syntax. Unicode digit lookalikes are not granted deletion authority. Legal `-Frag` text inside the 11-character YouTube video identity is also preserved, so an ID such as `abc-Frag123` cannot corrupt the stem used to discover and remove its own real `.part-FragN` siblings.

The decode adapter treats decoder-returned shape and dtype as untrusted even though the production call requests `mono=True` and `dtype=np.float32`. Multi-dimensional output is rejected instead of flattened, and integer, boolean, object, or complex output is rejected before any float32 conversion rather than being silently reinterpreted as real rehearsal PCM. Floating decoder output may be canonicalized only after the visible sample and byte budgets pass.

Persisted feature-cache replay is the same kind of trust transition. The cache path is app-owned, but persisted bytes are not treated as already-admitted PCM after a crash, restore, partial publication, version drift, corruption, or local modification. Before `np.load` may materialize a stem, the canonical replay owner requires a bounded regular archive, the exact unique `stem_<key>.npy` member set that the current writer emits, deflate compression without encryption, bounded version-1 NPY headers, and one-dimensional non-empty floating declarations whose sample counts, member extents, and aggregate declared bytes fit a policy derived from the cache's admitted sample rate. NumPy then loads from the same already-open archive with pickle disabled and the header ceiling preserved; legacy floating stems become owned native `float32` only after declaration admission, and `AudioResourcePolicy.validate_decoded_audio` rechecks shape, rate, samples, visible bytes, dtype and finiteness before MIR reuse. Unsupported or corrupt caches become misses and are recomputed through the canonical live path rather than being granted looser replay rules. This closes the persistence-bypass gap without claiming a process-wide NumPy/zlib allocation, decompression-time, CPU, RSS, disk-I/O, or privileged same-file-mutation ceiling.

The canonical decoded artifact ceiling is an artifact bound, not a process-memory promise. The returned decoder array is rejected on sample count, its visible `nbytes`, and the byte count that an owned canonical float32 copy would require before that copy is allocated. The last check matters when a narrower floating decoder dtype fits the visible buffer budget but expansion to float32 would not. If the decoder exposes a non-owning NumPy view, BandScope copies the admitted visible samples into a new owned canonical float32 array before returning the MIR artifact, so the artifact itself cannot keep a larger hidden backing allocation alive. Even a policy-admitted canonical copy can fail when the host allocator is exhausted; only that copy failure is surfaced as the payload-free `memory_budget_exceeded` policy rejection. Failure while first materializing an untrusted decoder result with `np.asarray` remains `malformed_header`, because the canonical-buffer admission boundary has not yet been reached. This preserves the distinction between malformed decoder materialization and admitted canonical-buffer exhaustion, but it still does not imply that the process stayed inside a measured RSS budget. Decoder/resampler allocations made inside `librosa` before return, the temporary coexistence of decoder and canonical buffers, and downstream NumPy/PyTorch/model/accelerator allocations must still be measured separately before setting CPU, RSS, GPU, or VRAM policy values. Canonical finiteness revalidation scans in chunks whose NumPy boolean mask is capped at 1 MiB rather than materializing a full-song mask. Sample reduction, unrealistic warm caches, or excluding expensive phases from the measurement do not satisfy this acceptance.

Subprocess output is likewise admitted rather than accumulated without a ceiling. The public desktop-core helper retains at most 1 MiB from stdout and 1 MiB from stderr and reads only one additional probe byte from either stream to establish overflow. The historical compatibility module no longer carries a second unbounded implementation; the bounded `process_output` module is the single execution owner behind the unchanged crate-root API. Overflow or stream-read failure maps to the existing payload-free process execution error before YouTube stdout is parsed as JSON. The reader that detects the violation sends a one-way failure signal to the process-control owner; the same loop waits on that channel for at most the smaller of the ordinary poll interval and the monotonic time remaining. A detected output failure therefore wakes the owner immediately, which terminates/reaps the helper boundary before joining the readers rather than letting a known admission violation wait for the next child-status poll. The same bounded wait also treats the configured timeout as a deadline, preventing a coarse poll interval from extending helper lifetime by another full interval. These controls bound retained parent memory and remove avoidable post-detection/deadline delay, while making no hard real-time scheduling claim and no whole-process RSS/VRAM, CPU, PID, or disk-quota claim.

Analysis JSONL is untrusted protocol input even after its byte budget. `start_analysis_job` creates the authoritative native job id and request timestamp. `run_analysis_engine` sends both values in the helper envelope, and every helper status must reproduce them exactly before native admission. The line transport removes only LF and an optional preceding CR; it does not call Unicode-aware `trim()` or otherwise normalize payload content before parsing. It also does not discard an empty physical record: after removing the line terminator, an empty payload is delivered to `serde_json` and rejected because there is no JSON value. That keeps RFC 8259 grammar and JSON Lines record validity with the parser instead of Resource Admission: ordinary JSON space/tab remains parseable, while a character such as U+00A0 cannot be stripped and a blank record cannot be erased to make a malformed stream appear valid. Each stdout line must then deserialize as `AnalysisJobStatus`; malformed JSON or schema-invalid status fails closed through the existing reader-failure channel instead of being ignored, and no later valid terminal line can rehabilitate that violation. Structural deserialization is followed by native semantic admission before any state mutation: `progressPercent` must remain within 0..=100; queued/running status cannot carry `result` or `error`; succeeded status must carry `result` and no `error`; failed status must carry `error` and no `result`. A typed helper status with another job id or another `requestedAt` likewise cannot be admitted into `status_tx`, stored under another concurrent job, or emitted to the renderer. The stdout reader then separates progress from completion: only a correctly keyed, request-time-bound, semantically admissible `Running` status may be streamed while the owned process is alive. A correctly keyed, request-time-bound, semantically admissible `Succeeded` or `Failed` record is retained privately as a completion candidate and becomes final native truth only after successful direct-child exit plus bounded-reader joins. Helper-authored `Queued` state is rejected because queue authority belongs to the native scheduler, and any record after a terminal candidate fails closed instead of reopening or overwriting completion. The failure channel remains the immediate wake-up path while the helper is running, but protocol rejection is also converted to a failing stdout-reader result before the thread returns. That second path closes the child-exit race: even if `try_wait()` observes a successful parent exit before the process-control loop consumes the failure notification, the subsequent reader join cannot present the rejected terminal candidate as a successful protocol stream. This prevents terminal UI/cancellation truth from getting ahead of actual process ownership. It does not establish the scientific correctness of progress labels, `updatedAt`, cache status, rehearsal results, or error meaning; those remain separate domain and real-audio validation concerns.

Request-time authority has its own deterministic RED. Rust RED `082cf63ee9007d0500b412e81a2910ac18b90e7a` requires the native envelope to carry `requestedAt`, retain the expected native value and compare it before helper status publication; Python RED `a253c099cb6781065f667e140968ab2a5fceeb91` requires a supplied native timestamp to survive `--progress-jsonl` unchanged. The predecessor Python CLI minted a new UTC timestamp independently, so both contracts were violated. Python production `9358035e96a091a9096e1760ed583a5a2dea190f` uses the supplied timestamp while retaining current-time fallback only for standalone/manual callers that omit it. Native production `70e4d9da09ab4d05c07afde0ea38adddc3265886` sends and exact-matches it before publication. RED and fixes were consecutive ordinary descendants, so hosted RED failure is not claimed; exact-head hosted verification belongs to the final current #866 head.

Hosted RED `e3a6a20a69581dd16d08668162b391892ad55573` proves the semantic gap was executable rather than documentary. The macOS Tauri test reached `analysis_status_payload_semantics_are_validated_before_native_state_mutation` and failed because the native validator did not exist. Production `2dbab44bf9a8a18b184a5371a6b7ad7d1efcd459` adds the single predicate and calls it before both running publication and terminal retention. It does not add a second process owner, renderer PID authority, or a new dependency.

Transport fidelity has its own deterministic RED. `e444365970a273e19c6c134064108bc0a8d59152` adds a bounded-line test requiring leading/trailing payload whitespace, including U+00A0, to survive transport. The predecessor's `str::trim()` violates that contract. Production `6258b97cc5c0981c8617c53f8b27375f882e3631` strips only the JSONL line ending and preserves the rest for parser authority. RED and fix were consecutive ordinary descendants, so hosted RED failure is not claimed; exact-head hosted verification belongs to the final current #866 head.

Blank-record fidelity has a separate deterministic RED. `161de8d6f2d9a1c9f0f6636983191953e07f3b57` changes the bounded-line contract to require the empty middle record in `"first\n\n second \n"` to reach the callback. The predecessor silently skipped that record, allowing a malformed JSONL stream to bypass the parser that is supposed to own record validity. Production `f8135e0ab691f075c3bb057ea4f52732c036a6fd` removes only that filter and forwards every byte-admitted physical record after CR/LF removal. The RED workflow was superseded/cancelled by the ordinary production descendant before Tauri execution, so hosted RED failure is not claimed; exact-head hosted verification belongs to the final current #866 head.

Child-exit ordering has a separate deterministic RED. `64cb603b128af1ec362932383ddca6a1b73f1c8b` requires protocol rejection to survive as a failing stdout-reader join result instead of existing only on the MPSC wake-up side channel. The predecessor could retain a valid terminal candidate, reject a later line, and still return `(Some(candidate), Ok(()))`; if the child exited before the main loop consumed the failure notification, post-exit finalization could therefore admit a protocol stream that had already been rejected. Production `ea9428cc6c9f61c7448959ed04f22a52ba013deb` maps `protocol_rejected` to `InvalidData` before returning from the reader thread while retaining the side-channel wake-up for the running-child path. RED and fix were consecutive ordinary descendants, so no hosted RED failure is claimed; exact-head hosted verification belongs to the final current #866 head.

Cancellation authority stays narrow: the renderer may refer to a BandScope-minted analysis job id, not a PID or generic process handle. Accepted cancellation and terminal publication remain one ordered decision. On Linux and macOS, `bandscope_desktop_core` owns process-group setup and termination. The native analysis runner delegates pre-spawn containment plus cancellation/timeout/error cleanup to that owner, and the timed YouTube import helper uses the same owner before joining stdout/stderr readers. One executable regression deliberately keeps a descendant alive through the timeout path and requires return in under one second rather than waiting for the five-second inherited pipe holder. A second regression covers the distinct success path: the direct parent exits successfully while a same-group descendant keeps stdout/stderr open; the shared owner must terminate the residual group before joining readers, so successful completion cannot hang behind a descendant that outlives its parent. A third regression emits helper output above the capture ceiling and requires fail-closed rejection instead of retaining the output until JSON metadata parsing. A fourth regression delays the over-budget write until after the parent has entered a two-second ordinary poll interval and requires fail-closed return in under one second, proving output-reader failure is an event wake-up rather than merely a condition sampled at polling cadence. A fifth regression gives a slow helper a 100 ms deadline but a two-second poll interval and requires timeout return in under one second; without deadline-clamped waiting, the poll interval itself would extend the resource lease. The bounded-line regression additionally requires an empty physical record to reach the protocol parser rather than disappearing below it. Tauri protocol regressions require the native job-id and request-time guards before helper status publication, require terminal/queued status to remain out of the pre-exit progress channel, require malformed/schema-invalid JSONL to wake the existing process owner, require semantic state/payload admission before native mutation, and require protocol rejection to remain a failed reader join result even when direct-child exit wins the race with the side-channel wake-up. A Tauri shell contract also rejects reintroduction of local `CommandExt`/`kill(2)` primitives and requires delegation to the shared core boundary. This closes the earlier DDD/SOLID drift risk without widening renderer authority.

The guarantee remains narrow. A descendant that deliberately changes process group or session is outside it, and Windows still falls back to direct-child termination until a race-free Job Object creation/assignment boundary is implemented. Commercial acceptance still requires Windows tree containment plus rights-cleared full-length real-audio evidence for cancellation latency, inherited pipe/handle release, child-created temp cleanup, and post-cancel resource return.

## Scientific and rehearsal acceptance

MIR claims must be reproducible from rights-cleared decoded audio and reported against recognized task metrics appropriate to the feature. Confidence is a claim boundary, not decoration: section, chord, stem, range, transcription, groove, and rehearsal-priority outputs must distinguish observed evidence, model inference, uncertainty, and unavailable evidence. A mock/generated-array success cannot substitute for production scientific acceptance.

The Active Player, Song Structure, Section Map, timeline and range controls must preserve the same actual-audio semantics through analysis, selection, persistence/reload, stale-source retirement, and playback. A persisted preference alone never authorizes stale media. Full mix fallback is the safe audible default when a requested stem cannot be freshly re-admitted.

Current commercial Release Gate: **FAIL**.

A release-ready protected head must have code-current version and CHANGELOG, terminal required CI/security evidence, Windows signing, macOS signing and notarization, packaged artifacts, SBOM/provenance, reproducibility evidence, immutable tag/release publication, and updater rollback evidence. Technical model compatibility does not establish model redistribution rights, and a successful local build does not establish signing/notarization or updater safety.

## Security Notes

Untrusted boundaries include local audio and project files, URLs, score PDFs, subprocess/model outputs, persisted feature caches, IPC, model artifacts, update artifacts, metadata and logs. Keep allowlists and bounded reads at the owner boundary, keep external paths/PIDs/generic process handles out of renderer authority, fail closed with payload-safe diagnostics, and keep resource/security provenance path-free where it crosses product contracts. Path-free native publication identity must be validated on deserialization through the same project-id, extension, byte-range, digest and derived-artifact-name invariants used to mint it; Serde shape validation alone is not authority. Security fixes belong to their canonical owner; do not weaken gates, add synthetic statuses, restore duplicate scanners, or copy mutable sibling source to make a consumer appear green.
