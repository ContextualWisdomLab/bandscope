## 2024-05-19 - Replace HTML disabled with aria-disabled="true" for Accessible Tooltips
**Learning:** Native HTML `disabled` attributes completely hide elements from screen readers and block all pointer/hover events, preventing tooltips from functioning for disabled elements.
**Action:** Replace `disabled` with `aria-disabled="true"`, enforce block click handlers via `e.preventDefault()`, and add a title tooltip directly to the element to maintain full tooltip accessibility and keyboard focus support for visually impaired and mouse users.
## 2026-10-02 - PracticeProgress Tooltip Accessibility
**Learning:** `aria-label` attributes on `<button>` elements are often insufficient for icon-only buttons as they don't provide visual feedback on hover/focus. Replacing native `title` attributes with a custom `<Tooltip>` component provides immediate visual context and robust screen reader support. Wait, `TooltipProvider` should wrap the `<Tooltip>` component if it is used, or the component itself can use `<TooltipProvider>` inside it, but `delay` goes on `TooltipProvider`. When testing tooltips, avoid checking `toBeDisabled` and use `toHaveAttribute("aria-disabled", "true")`. Using `await screen.findByRole` handles async tooltip rendering in tests.
**Action:** When creating icon-only buttons, consistently use the UI library's `<Tooltip>` component instead of native `title` or just `aria-label`. Ensure tests await the button asynchronously if wrapped in a tooltip, and verify the `delay` prop is applied to the correct component (`TooltipProvider` vs `Tooltip`).
