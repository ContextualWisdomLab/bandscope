# Persisted feature-cache resource admission

## Scope and decision

BandScope treats the persisted stem-feature cache as a Resource Admission & Decode boundary rather than trusted in-memory state. The cache lives below an app-owned path, but a crash, interrupted publication, restore, local tampering, or version drift can leave bytes that no longer satisfy the live decode/model invariants. Replaying those bytes directly into MIR would let persistence bypass the controls applied to freshly decoded or separated audio.

The selected design keeps one cache replay owner: `feature_cache_admission.load_bounded_stem_archive`. `_load_cached_local_audio_features` validates its metadata/separation/role envelope, then delegates the stem archive to that owner with the live `DEFAULT_AUDIO_RESOURCE_POLICY`. No second archive/resource policy is introduced in API, persistence, or MIR code.

RED `fabad0c563eb5fc11dbba3ad9adf4960684f2249` requires finite floating legacy cache stems to become owned native NumPy `float32`, rejects multidimensional/non-finite stems and unsupported sample rates, and requires a member whose declared PCM exceeds policy to fail before `np.load` can materialize it. Production prerequisite `9fa37096985063a3ede6e79075377a471ec24109` implements the bounded archive owner. Integration `c9296732aa331f77f433bc49258c6d493ecc492a` replaces API's direct `np.load` replay with that owner; ordinary descendant `7047b215330c0f189eb5e7e35591824000929869` restores unrelated docstring text accidentally changed during the contents-API write without rewriting history.

A second trust-boundary review found that the first bounded archive owner still accepted any Python identifier as a persisted stem name. That was broader than the production separation contract, whose rehearsal evidence is the four canonical `vocals`, `bass`, `drums`, and `other` stems. A tampered cache could therefore manufacture a fifth semantic stem such as `guitar` even though the canonical separator never emitted it. RED `ef1e0c932d3ca3be690b68ca479e11843412a5ef` pins that cache replay must reject an invented stem identity. Production `da4916f9cb1d221a4ba35001d26a51c54907016b` admits only a unique non-empty subset of the four canonical stem names before ZIP member inspection or NumPy materialization. The RED head was superseded before functional CI execution, so hosted RED failure is not claimed.

A later replay review found a separate scientific-integrity gap: the archive preflight admitted each stem independently but did not require all admitted stems to describe the same number of samples. Source-separation stems are synchronized estimates on one mixture timeline; replaying a 16-sample bass stem beside an 8-sample drums stem is therefore not a valid partial-cache representation of one separated song and can make section/activity reasoning depend on malformed persistence rather than the decoded source. RED `c2e44845b4f403652f6c6be3a36aa8641ad09648` adds a two-stem compressed archive whose declared NPY shapes disagree and requires rejection before `np.load`. Production `79c31f560ef68ae5190852294a8f7fcfa9ccb424` records the first admitted member's sample count during declaration preflight and requires every later canonical member to match it. The control is deliberately declaration-first: a malformed synchronized-timeline cache is a miss before NumPy materializes either waveform.

A fresh availability review then found that declaration admission did not contain allocator failure at the final NumPy archive-open boundary. `np.load` can still require interpreter/native allocations after the ZIP/NPY declarations have passed the product's visible-byte checks. If that operation raises Python `MemoryError`, the previous outer replay guard allowed it to escape instead of converting the unusable persisted artifact into a cache miss. RED `1c47cd7cc3a04bb6e98a995bd916267ca1b5687f` injects allocator exhaustion at that exact admitted-archive boundary and requires the analysis job to continue through the canonical cache-miss path. Production `b34e4ade955ce22c70e0365c18fc510bfdfc5f2b` catches `MemoryError` (and truncated `EOFError`) both during declaration preflight and final NumPy archive open. This is fail-closed error containment, not evidence that BandScope can reserve enough memory for every admitted archive.

A subsequent TOCTOU review found a narrower generation-consistency defect inside the same replay owner. `_load_cached_local_audio_features` reads `stemKeys` from the metadata sidecar, then the archive owner reopens that sidecar before materialization. The second read previously checked canonical role values but did not prove that the reopened sidecar still described the same stem identity. A replacement sidecar could therefore change `stemKeys` between the two reads while retaining a role entry for the first-read key. RED `34e1bdc3756f446b72399179cff0757efe56eadd` replaces an initially valid `bass` sidecar with a `drums` sidecar and requires the second-read admission to fail. Production `ee0d79d81e9f42e041abf5013299df7f0f5b5cbe` requires the reopened sidecar's `stemKeys` list to equal the caller's already-admitted list and, when `stemRoleTypes` is present, requires its key set to equal that same identity before checking canonical role bindings. This closes stem-identity substitution at the existing second-read boundary without claiming that metadata, archive bytes, sample rate, and source content are yet one atomic generation.

## Invariants

The replay path admits the already-open archive before any stem array is materialized. The file must be a non-empty regular file within the aggregate archive bound. The metadata may name one to four unique stems, but every name must belong to the current canonical separation output set: `vocals`, `bass`, `drums`, or `other`. An arbitrary identifier is not sufficient evidence of a valid stem identity. When the archive owner reopens the metadata sidecar, its persisted `stemKeys` must exactly match the caller's already-admitted list; a second-read sidecar describing another stem set is a cache miss. If `stemRoleTypes` exists, it must describe exactly those same keys with the canonical role binding. The ZIP central directory must contain exactly the corresponding `stem_<key>.npy` members: no extras, duplicates, directories, encrypted entries, or compression methods other than `ZIP_DEFLATED` are accepted.

Each member must fit the policy-derived decoded-byte ceiling plus the bounded NPY header allowance. BandScope reads the NPY magic and version-1 header through the compressed member stream before calling `np.load`; it requires one non-empty, C-order floating array and checks declared sample count, declared element bytes, and exact header-plus-data extent against the member's declared uncompressed size. Aggregate declared member bytes are also bounded. Once the first member establishes the archive's sample count, every remaining admitted stem must declare exactly that same count. BandScope does not truncate, pad, stretch, or otherwise fabricate synchronization during replay.

Only after that declaration preflight does BandScope rewind the same already-open archive and call `np.load(..., allow_pickle=False, max_header_size=16 KiB)`. A loaded legacy floating dtype is copied into owned `float32` only after the earlier declared sample/byte checks. Every loaded stem is then re-admitted through `AudioResourcePolicy.validate_decoded_audio`, which rechecks sample rate, one-dimensional shape, canonical dtype, sample count, visible bytes, and finiteness before the array can return to MIR/rehearsal analysis. `EOFError`, `MemoryError`, malformed ZIP/NPY state, or other admitted format failures at the archive owner are cache misses; they are not allowed to escape as analysis-job failures merely because the path had already passed declaration checks.

## Alternatives considered

Direct `np.load` followed by post-load validation was rejected because decompression/materialization itself would remain outside the product's resource-admission boundary. Trusting the app-owned cache directory was rejected because ownership of a path is not evidence that persisted bytes remain well-formed after crashes, restores, corruption, or local modification. Re-implementing NPY payload decoding was also rejected: BandScope only parses the bounded declaration needed to decide whether materialization is admissible, then delegates actual NumPy format decoding to NumPy with pickle disabled and an explicit header ceiling.

Accepting arbitrary identifier-shaped stem names was rejected because lexical validity does not establish rehearsal-domain provenance. The persisted cache is allowed to contain a subset of the canonical four stems, preserving partial-cache compatibility, but it cannot expand the separator's domain vocabulary. Requiring all four stems on every replay was also rejected because the existing cache contract permits a bounded subset and completeness is a different invariant from identity authority.

Trusting the first metadata read while treating the second sidecar read as role-only metadata was rejected because the pathname can resolve to another valid sidecar between those operations. MITRE CWE-367 describes this class as a check/use race where resource state changes after validation. Requiring the second-read `stemKeys` to equal the caller's admitted identity is a minimal causal guard that preserves the current owner structure. It is not a substitute for the planned immutable generation/digest contract, because a same-stem-key replacement can still alter other metadata fields between reads.

Truncating every persisted stem to the shortest member, zero-padding shorter members, or resampling one member to another member's declared length was rejected. Those repairs would manufacture a common timeline after persistence corruption and could shift onset, activity, section, or handoff evidence. A cache miss is cheaper and scientifically safer because the canonical live separation path can regenerate synchronized stems from the admitted source.

Letting `MemoryError` propagate after declaration admission was rejected because a persisted cache is optional acceleration, not authoritative rehearsal truth. If the interpreter reports that archive opening or materialization cannot obtain memory, the safe product action is to abandon that persisted artifact and let the caller recompute or degrade through the existing cache-miss path. Catching the exception does not replace process-level RSS limits or capacity planning; it only keeps the persistence boundary from converting an optional cache failure into a hard analysis crash.

Supporting every NPY/ZIP representation was rejected for this cache version. The current writer uses `np.savez_compressed`; replay therefore accepts the narrow version-1 NPY / deflate representation that BandScope itself emits and fails closed on representation drift. A future cache-format migration must be versioned and tested rather than silently widening the parser surface.

## Security Notes and claim boundary

Python's `zipfile` exposes member `file_size`, `compress_size`, compression method, encryption flag bits, and ordered member metadata before extraction. NumPy documents `.npz` as a ZIP-backed dictionary-like container whose arrays are loaded lazily, and `numpy.load` explicitly recommends `allow_pickle=False` for safer handling of untrusted data and supports a bounded `max_header_size`. Those APIs make declaration-first admission possible, but their existence is not itself a resource guarantee; BandScope supplies the product limits, canonical stem vocabulary, exact-member contract, synchronized-timeline invariant, and failure containment.

Python documents `MemoryError` as the exception raised when an operation runs out of memory in a situation that may still be recoverable, while noting that recovery is not guaranteed by the interpreter's memory-management architecture. BandScope therefore catches it narrowly at this optional persisted-cache boundary and returns a cache miss. It does not catch process termination by the operating system, prove that memory is available, or reinterpret allocator exhaustion as a successful cache replay.

MITRE CWE-367 defines TOCTOU as checking resource state and then using the resource after its state can change, invalidating the check. The current second-read identity check prevents one concrete substitution: a sidecar reopened by the archive owner cannot silently describe a different `stemKeys` list than the caller already admitted. It does not make two pathname reads atomic, does not lock the sidecar, and does not bind same-identity metadata replacement to the already-open NPZ or the admitted source. Full persistence integrity still requires one immutable generation/digest authority or an equivalent transaction that binds metadata, archive, and source content.

Demucs is a waveform-to-waveform music-source-separation model, and the BandScope separator contract turns one admitted mixture into canonical stem waveforms intended to remain aligned on that mixture's analysis timeline. The cache therefore preserves sample-count alignment as domain evidence rather than treating independently valid arrays as a valid multi-stem song. This does not imply sample-level separation accuracy: bleed, interference, and model error remain scientific-quality concerns measured separately from persistence integrity.

This control bounds the cache artifact that BandScope elects to materialize and prevents persisted metadata from manufacturing a noncanonical stem identity, substituting a different second-read stem set, or combining canonical stems with contradictory declared timeline lengths. It does **not** establish a whole-process memory, CPU, disk-I/O, or decompression-time ceiling for Python, NumPy, zlib, or downstream MIR/model execution. It also does not make the already-open file an immutable content snapshot against a privileged local actor capable of modifying bytes in place. Full commercial resource acceptance therefore still requires rights-cleared full-length rehearsal audio with measured peak RSS/VRAM, CPU/GPU budgets, cancellation latency, inherited handle/pipe return, and child-created temporary-file cleanup.

A corrupt, unsupported, semantically noncanonical, desynchronized, truncated, allocation-unserviceable, or identity-substituted cache is a cache miss, not rehearsal evidence. The caller may recompute features through the canonical live path; it may not relax admission to preserve cache hit rate.
