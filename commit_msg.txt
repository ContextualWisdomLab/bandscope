🔒 Fix path traversal vulnerability in cacheRoot and tempRoot validation

🎯 **What:** The vulnerability fixed
Path traversal vulnerability in the `tempRoot` and `cacheRoot` parameters passed to `validate_analysis_job_request` which allowed relative paths such as `../` to be injected. This could result in temporary and cache files being written outside of the intended app-owned directory structure. Additional fixes include path traversal prevention for `localSource.sourcePath` and limiting the level of detail disclosed in error messages.

⚠️ **Risk:** The potential impact if left unfixed
An attacker (or malicious project file) could exploit this by setting `tempRoot` or `cacheRoot` to paths containing `../` to escape the temporary directory. If successfully exploited, arbitrary app-owned directories could be targeted, leading to file overwrites, unauthorized access, or corruption of local system files. Furthermore, verbose error messages could leak sensitive system information.

🛡️ **Solution:** How the fix addresses the vulnerability
Added sanitization logic to the validation of `cacheRoot`, `tempRoot`, and `localSource.sourcePath`. The new checks enforce that the path segments do not contain `".."`, immediately raising a `ValueError` if a path traversal attempt is detected. Error messages have been generalized to avoid exposing internal logic or exception details. Corresponding tests have been updated and added to ensure the safety conditions hold. Also, missing test docstrings have been added. Also resolved `interrogate` crashing on non UTF-8 encoded files within `site-packages` by excluding `site-packages`.
